# Set Up Your Software Environment
Before basecalling, set up your software environment to run Dorado inside an Apptainer container.

If you are not already logged into the CHTC Access Point (AP), do so now via SSH:
```bash
ssh <user.name>@ap####.chtc.wisc.edu
```

:::{seealso} Never Built an Apptainer Container Before?
If you have never built an Apptainer container before, refer to the [Apptainer Container Building Guide](https://chtc.cs.wisc.edu/uw-research-computing/apptainer-htc) for more information on building Apptainer containers on CHTC.
:::

# Write Your Dorado Apptainer Definition File

1. Create a definition file for Apptainer to build your Dorado container. Open a text editor, such as `vim` or `nano`, and save the following as `software/dorado.def`:

   ```{code} bash
   :filename: software/dorado.def
   :linenos:
    Bootstrap: docker
    From: nvidia/cuda:13.0.1-cudnn-runtime-ubuntu22.04
    
    %post
        DEBIAN_FRONTEND=noninteractive
    
        # system packages
        apt-get update -y
        apt-get install -y python3-minimal curl
        curl -sS https://bootstrap.pypa.io/get-pip.py -o get-pip.py
        python3 get-pip.py --break-system-packages
        rm get-pip.py 
        apt-get install -y bedtools
    
        # install Dorado and POD5
        cd /opt/
        curl -L https://cdn.oxfordnanoportal.com/software/analysis/dorado-1.2.0-linux-x64.tar.gz -o ./dorado-1.2.0-linux-x64.tar.gz
        tar -zxvf dorado-1.2.0-linux-x64.tar.gz
        rm dorado-1.2.0-linux-x64.tar.gz
    
        # install POD5 using pip
        pip install pod5 --break-system-packages
    
    %environment
        # set up environment for when using the container
        # add Dorado to $PATH variable for ease of use
        export PATH="/opt/dorado-1.2.0-linux-x64/bin/:$PATH"
    ```

    This definition file uses the Nvidia CUDA `13.0.1` libraries on an Ubuntu `22.04` base image and installs necessary packages to run Dorado and POD5 in an Apptainer container.

:::{tip} CUDA Containers can get very large!
CUDA base images can be quite large (several GBs). This is normal due to the inclusion of GPU drivers and libraries. You may run into issues with insufficient quotas in your `/staging` directory if you have limited space available. You might also run into issues with your jobs not starting if there is insufficient space on the Execution Point (EP) nodes to store the container image. Ensure you have sufficient quota in your `/staging` directory and request sufficient disk in your job submit file to store the final container image, which may be several GBs in size.
:::

# Build Your Dorado Apptainer Container Interactively

## Write Your `build.sub` Submit File

2. Create a submit file to build your Dorado Apptainer container interactively on the Access Point (AP). Open a text editor, such as `vim` or `nano`, and save the following as `software/build.sub`:

   ```{code} bash
   :filename: software/build.sub
   :linenos:
   :emphasize-lines: 3,8
   log = $(job_name).log
   
   transfer_input_files = software/dorado.def
   
   +IsBuildJob = True
   
   request_cpus = 8
   request_memory = 24GB
   request_disk = 30GB
   
   queue
   ```

   :::{attention} Make sure to update the `transfer_input_files` and `request_disk` value!
    - Ensure that the `transfer_input_files` attribute points to the correct location of your `software/build.sub`.
    - The `request_disk` value should be set high enough to accommodate the size of the final container image. CUDA-based containers can be quite large (several GBs). If you encounter disk space errors during the build process, increase this value accordingly.
    - You can also adjust the `request_cpus` and `request_memory` values based on your system's capabilities and the requirements of the build process.
   :::

3. Submit your build job to HTCondor:
   
   ```{code} bash
   condor_submit -i software/build.sub
   ```

   :::{hint} Interactive Job Session 
    After submitting the job, HTCondor will allocate resources on a dedicated container-building Execution Point (EP) and start an interactive session. You will be logged into the EP where you can build your Apptainer container. You will notice your command prompt changes to indicate you are on the EP.
   
   ```{code} bash
   :linenos:
   :emphasize-lines: 1,9
   :caption: Notice the change in hostname from ap2002 to build4001 on lines 1 and 9.
   [bbadger@ap2002 ~]$ condor_submit -i
   Submitting job(s).
   1 job(s) submitted to cluster 4650597.
   Waiting for job to start...
   Welcome to interactive3_1@build4001.chtc.wisc.edu!
   You will be logged out after 7200 seconds of inactivity.
   == NOTICE: THIS NODE IS ON PUPPET ENVIRONMENT "puppet8" ==
   
   [bbadger@build4001 scratch]$ 
   ```
   :::

4. Once logged into the AP, `ls -lh` the directory:
   
   ```{code} bash
   [damorales4@build4001 scratch]$ ls -lh
   total 12K
   drwx------ 3 damorales4 damorales4 4.0K Jan  9 16:23 home
   drwx------ 2 damorales4 damorales4 4.0K Jan  9 16:23 tmp
   drwx------ 3 damorales4 damorales4 4.0K Jan  9 16:23 var
   -rw-r--r-- 1 damorales4 damorales4  12K Jan  9 16:23 dorado.def
   ```
   
   Notice your `dorado.def` file has been transferred to the EP. This is the file you will use to build your Dorado Apptainer container.

## Build Your Dorado Apptainer Container

5. Build your Apptainer container on the Access Point (AP):

    ```bash
    apptainer build dorado_build1.2.0_27OCT2025_v1.sif dorado.def
   ```
   
   :::{attention} Naming Your Container Image
    It is good practice to include the software name, version, build date, and any other relevant information in the container image name. This helps with version control and makes it easier to identify the container later. In this example, the container is named `dorado_build1.2.0_27OCT2025_v1.sif`, indicating it is a build of Dorado version `1.2.0`, built on `27OCT2025`, and is version `1` of this build.
   
   This is especially important for using the `osdf:///` transfer protocol to move your container from your `/staging` directory into your Dorado jobs later on. The `osdf:///` protocol requires a unique and descriptive name to avoid conflicts with other cached versions of your container images.
    :::
   
   :::{hint} Your build process may take several minutes.
    The build process involves downloading and installing several packages and dependencies, which can take some time depending on your network speed and the load on the build node. Be patient while the build completes. 
   :::

# Move Your Dorado Apptainer Container to Your `/staging` Directory
6. Move your finalized container image, `dorado_build1.2.0_27OCT2025_v1.sif`, to your `/staging` directory
    
    ```bash
   mv dorado_build1.2.0_27OCT2025_v1.sif /staging/<netid>/tutorial-ONT-Basecalling/software/
   ```
   
# Downloading the Dorado Basecalling Models
Dorado basecalling models are not included in the Dorado Apptainer container image by default. As a result, we must download the models we wish to use for basecalling prior to submitting our basecalling jobs. We can download the models directly using the Dorado command line interface (CLI) within our Dorado Apptainer container.

:::{warning} Do not download the models into your container image!
While it may be tempting to include the models directly in your Apptainer container image during the build process, this is not recommended. The models can be quite large and including them in the container will significantly increase the size of the image, making it cumbersome to transfer and use. Further, any updates to the models would require rebuilding the entire container image. Instead, download the models to your `/staging` tutorial directory as described below.
:::

7. Launch an interactive Apptainer shell session on the Access Point (AP) using your `dorado_build1.2.0_27OCT2025_v1.sif` container:
    
   ```bash
    cd /staging/<netid>/tutorial-ONT-Basecalling/
    apptainer shell --bind "$PWD" software/dorado_build1.2.0_27OCT2025_v1.sif
   ```

8. Download your desired Dorado model (e.g. `dna_r10.4.1_e8.2_400bps_hac@v5.2.0`) to your `data/` directory in your OSPool tutorial directory:

    ```bash
   dorado download --model dna_r10.4.1_e8.2_400bps_hac@v5.2.0 --models-directory /staging/<netid>/tutorial-ONT-Basecalling/data/
    ```

:::{note} Selecting Different Models
This step will download the requested Dorado basecalling model. If you only wish to download specific models, you can replace the `--model dna_r10.4.1_e8.2_400bps_hac@v5.2.0` argument with `--model <model_name>`, where `<model_name>` is the name of the model you wish to download (e.x. `duplex_sup@v5.2.0`). You can also download all the available models (not recommended as there are many models) using the `--model all` option. Not sure which model to use? Refer to the [Model Selection - Dorado documentation](https://software-docs.nanoporetech.com/dorado/latest/models/selection/) for more information on selecting the appropriate model for your data.
:::

9. Exit the Apptainer shell:
    ```bash
    exit
    ```

10. Compress the models into tar.gz files for efficient transfer to the Execution Point (EP) during job submission:

    ```{code} bash
    :caption: The following command compresses the downloaded model directory into a tar.gz file and **then removes the uncompressed directory** to save space.
    cd /staging/<netid>/tutorial-ONT-Basecalling/data/
    tar -czf dna_r10.4.1_e8.2_400bps_hac@v5.2.0.tar.gz dna_r10.4.1_e8.2_400bps_hac@v5.2.0 && rm -rf dna_r10.4.1_e8.2_400bps_hac@v5.2.0/ 
    ```

   :::{warning} Keep the tar.gz files!
    Keep the compressed tar.gz files of the models, as these will be transferred to the Execution Point (EP) during job submission for basecalling. The uncompressed model directories are no longer needed on the AP and can be removed to save space.
   :::
