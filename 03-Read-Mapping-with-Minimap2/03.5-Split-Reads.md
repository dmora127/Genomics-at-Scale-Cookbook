---
title: "Split Your Reads into Chunks"
subtitle: "Mapping Long Reads with Minimap2 on CHTC"
short_title: Split Reads
---

To map the reads as many parallel jobs, cut the FASTQ file into chunks and write a list of the chunk names. Each name in the list becomes one HTCondor job in the next step. This step runs on the Access Point and does not depend on the indexing job, so you can do it while the index is being built.

## Split the Reads

1. Move to your `inputs/` directory, where the compressed reads are:

   ```bash
   cd ~/genomics_tutorial/inputs/
   ```

2. Decompress the reads on the fly and split them into chunks of 4,000 lines. A FASTQ record is four lines, so each chunk holds 1,000 reads:

   ```bash
   zcat sd_0001_sub.fastq.gz | split -l 4000 - subset_
   ```

   `split` names its output files with the prefix `subset_` followed by two letters: `subset_aa`, `subset_ab`, and so on. The toy dataset has 261,044 reads, so you get 262 chunks, `subset_aa` through `subset_kb`, the last of which holds the remaining 44 reads. Minimap2 does not care that the files have no `.fastq` extension.

   :::{warning} Only write the chunks to your `/home` directory!
   **Never write hundreds of small files to `/staging`.** `/staging` is designed for large files, and writing many small files to it strains the shared storage system for everyone and violates the CHTC `/staging` usage policy. The read chunks are small and used once, so they belong in your `/home` directory, from where HTCondor transfers them into the jobs directly.
   :::

   :::{tip} Choosing a chunk size
   One thousand long reads per job is at the small end: each job spends a noticeable share of its time loading the multi-gigabyte index. For your own data, chunks of 10,000 to 50,000 reads (`-l 40000` to `-l 200000`) give jobs that run for tens of minutes, which is a comfortable size for HTCondor. If you need more than 676 chunks, add `-a 3` to `split` so that it uses three-letter suffixes.
   :::

3. Check the result:

   ```
   [<netid>@ap2001 inputs]$ ls subset_* | wc -l
   262
   [<netid>@ap2001 inputs]$ ls subset_* | head -3
   subset_aa
   subset_ab
   subset_ac
   ```

## Create the List of Chunks

4. Write the chunk names, one per line, to `listofReads.txt` in your project directory:

   ```bash
   ls subset_* > ~/genomics_tutorial/listofReads.txt
   ```

   If you `head` this new file you should see output similar to this:

   ```
   [<netid>@ap2001 inputs]$ head ~/genomics_tutorial/listofReads.txt
   subset_aa
   subset_ab
   subset_ac
   subset_ad
   subset_ae
   subset_af
   subset_ag
   subset_ah
   subset_ai
   subset_aj
   [<netid>@ap2001 inputs]$
   ```

   This list is your list of jobs. The submit file in the next step reads it line by line and creates one mapping job per chunk. The idea of a **list of jobs** is central to how HTCondor and high-throughput computing work: the submit file describes one job, and the list says how many times, and with what input, to run it.
