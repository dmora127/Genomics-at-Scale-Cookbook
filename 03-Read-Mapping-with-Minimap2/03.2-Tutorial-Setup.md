## Before You Begin

You will need the following before moving forward with the tutorial:

1. A CHTC HTC account. If you do not have one, request access at the [CHTC Account Request Page](https://chtc.cs.wisc.edu/uw-research-computing/form.html).
2. A CHTC `/staging` directory for large files. If you do not have one, request it through the [CHTC large data guide](https://chtc.cs.wisc.edu/uw-research-computing/file-avail-largedata).
3. Basic familiarity with HTCondor job submission. If you are new to HTCondor, complete the CHTC [Roadmap to getting started](https://chtc.cs.wisc.edu/uw-research-computing/htc-roadmap) and read [Practice: Submit HTC Jobs using HTCondor](https://chtc.cs.wisc.edu/uw-research-computing/htcondor-job-submission).
4. Basic familiarity with the Linux command line. If you are new to the command line, consider working through the [Unix Shell](https://swcarpentry.github.io/shell-novice/) lesson from Software Carpentry.
5. A general understanding of the long-read sequencing analysis workflow: basecalling, quality control, mapping, variant calling. The [Dorado](../01-Basecalling-GPUs/01.1-Introduction.md) and [FastQC](../02-Quality-with-FASTQC/02.1-Introduction.md) recipes cover the first two steps.
6. About 10 GB of free space in your `/home` directory (the reference, the reads, the read chunks, and the BAM files) and about 5 GB in your `/staging` directory (the container image and the index). Check with `quota -vs`; see the CHTC guide on [checking disk quota and usage](https://chtc.cs.wisc.edu/uw-research-computing/check-quota).

:::{hint} No need to be a genomics expert!
You do not need to be a genomics expert to follow this tutorial. The commands and scripts are beginner-friendly and self-contained while reflecting real-world research workflows.
:::

:::{note} Versions used in this tutorial
| Component | Value |
|-----------|-------|
| Minimap2 | 2.30-r1287 |
| samtools | 1.22.1 |
| bedtools | 2.31.1 (installed in the container, not used in this tutorial) |
| Container base image | `continuumio/miniconda3:latest` as of 8 October 2025 |
| Container image | `minimap2_08OCT2025_v1.sif` (662 MB), prebuilt by CHTC |
| Reference genome | `G_californianus_813.fasta`: NCBI assembly ASM1813914v2 of California condor isolate 813, 542 sequences, 1.2 GB |
| Reads | `sd_0001_sub.fastq.gz`: 261,044 Oxford Nanopore reads from a California condor, 2.3 GB compressed |

The container recipe `software/minimap2.def` does not pin the tool versions, so a container you build yourself will pick up whatever bioconda serves that day. Pin the versions in the recipe when you adapt it for your own work.
:::

## Materials

Log into a CHTC Access Point (AP):

```bash
ssh <netid>@ap2001.chtc.wisc.edu
```

Clone the companion tutorial repository, which contains the executables, submit files, and container definitions used in this tutorial:

```bash
git clone https://github.com/dmora127/CHTC-BioCafe-Fall25-Minimap2.git
```

The repository keeps its files under `genomics_tutorial/home/` and `genomics_tutorial/staging/`, mirroring where they belong on CHTC. Copy them into a working directory in `/home` and a companion directory in `/staging`:

```bash
mkdir -p ~/genomics_tutorial/
cp -r ~/CHTC-BioCafe-Fall25-Minimap2/genomics_tutorial/home/* ~/genomics_tutorial/

mkdir -p /staging/<netid>/genomics_tutorial/
cp -r ~/CHTC-BioCafe-Fall25-Minimap2/genomics_tutorial/staging/* /staging/<netid>/genomics_tutorial/
```

Then copy the toy dataset and the prebuilt container image from the shared CHTC staff directory. The reads and the reference go to `/home`; the container image goes to `/staging`:

```bash
cp /staging/groups/chtc_staff/sd_0001_sub.fastq.gz ~/genomics_tutorial/inputs/
cp /staging/groups/chtc_staff/G_californianus_813.fasta ~/genomics_tutorial/inputs/
cp /staging/groups/chtc_staff/minimap2_08OCT2025_v1.sif /staging/<netid>/genomics_tutorial/software/
```

:::{tip} Copy the three files in parallel
The three copies are independent, so you can run them at the same time and wait for all of them to finish:

```bash
(cp /staging/groups/chtc_staff/sd_0001_sub.fastq.gz ~/genomics_tutorial/inputs/ & \
 cp /staging/groups/chtc_staff/G_californianus_813.fasta ~/genomics_tutorial/inputs/ & \
 cp /staging/groups/chtc_staff/minimap2_08OCT2025_v1.sif /staging/<netid>/genomics_tutorial/software/ & wait)
```
:::

:::{note} About the `<NetID>` placeholder
The submit files in the companion repository spell the NetID placeholder `<NetID>`. This cookbook writes it `<netid>`. Either way, replace it with your own NetID wherever it appears.
:::

## About the Toy Dataset

The toy dataset comes from the California condor (*Gymnogyps californianus*), North America's largest land bird and one of its most endangered, with a population that fell to 27 individuals in 1987 before a captive-breeding program rebuilt it. The reference genome is the NCBI assembly ASM1813914v2 of condor isolate 813, which is why the FASTA file is named `G_californianus_813.fasta`. The reads are a subset of 261,044 Oxford Nanopore whole-genome sequencing reads from a condor, with the read names replaced by short anonymous identifiers.

The dataset is small enough to complete the tutorial in a reasonable amount of time, while still being representative of real-world data: the reference is over a gigabase, and the reads are long enough that each mapping job does real work.

## Time Estimation

Plan about 1-1.5 hours for the tutorial walkthrough. The indexing job runs for about ten minutes once it starts. Each mapping job runs for a few minutes, and the 262 mapping jobs typically all finish within half an hour of submission, depending on cluster load.

## Recommended Directory Structure

After the setup steps above, your working directory in `/home` has the layout below. The `inputs/`, `logs/`, and `outputs/` directories fill up as you work through the tutorial:

```bash
~/genomics_tutorial/
├── executables/
│   ├── minimap2_index.sh          # builds the .mmi index (one job)
│   └── minimap2_mapping.sh        # maps one chunk and sorts the result (one job per chunk)
├── inputs/                        # reference FASTA, reads, and the subset_* chunks
│   ├── G_californianus_813.fasta
│   └── sd_0001_sub.fastq.gz
├── listofReads.txt                # one chunk name per line (created in Split Your Reads)
├── logs/                          # HTCondor .log, .out, and .err files
├── minimap2_index.sub             # submit file for the indexing job
├── minimap2_mapping.sub           # submit file for the mapping jobs
├── outputs/                       # sorted BAM files returned by the mapping jobs
└── software/
    ├── minimap2.def               # container recipe (Minimap2, samtools, bedtools)
    └── sniffles2.def              # container recipe for Sniffles2 (a next step, not used here)
```

You also have a companion **`/staging`** directory for the two large files that every mapping job needs:

```bash
/staging/<netid>/genomics_tutorial/
├── inputs/
│   └── G_californianus_813.fasta.mmi      # reference index (written by the indexing job)
└── software/
    └── minimap2_08OCT2025_v1.sif          # container image
```
