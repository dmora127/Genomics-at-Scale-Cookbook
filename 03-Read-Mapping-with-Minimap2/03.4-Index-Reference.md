(minimap2-index-reference)=
Before mapping, build the Minimap2 index of the reference genome. This is a single job: it reads the 1.2 GB FASTA, writes a `.mmi` index file, and places the index in your `/staging` directory, where every mapping job can fetch it through OSDF.

## Prepare the Indexing Job: Executable and Submit File

### The Executable File: `minimap2_index.sh`

1. Change to your `genomics_tutorial/` directory:

   ```bash
   cd ~/genomics_tutorial/
   ```

2. Review the executable `executables/minimap2_index.sh`. No changes are necessary:

   ```{code} bash
   :filename: executables/minimap2_index.sh
   :linenos:
   #!/bin/bash
   minimap2 -x map-ont -d "${1}.mmi" "$1"
   ```

   The script takes one argument, the name of the reference FASTA file, and writes the index next to it as `<name>.mmi`. The `-x map-ont` preset matters here as well as at mapping time: the preset sets the k-mer and window sizes that the index is built with, so build the index with the same preset you will map with.

### The Submit File: `minimap2_index.sub`

3. Open `minimap2_index.sub` and fill in the placeholders. The cloned file has `<input_ref_genome_fasta_file_name>` in four places and `<NetID>` in two; replace them so that the file reads as follows:

   ```{code} bash
   :filename: minimap2_index.sub
   :linenos:
   :emphasize-lines: 1,4,6,8-10
   container_image        = osdf:///chtc/staging/<netid>/genomics_tutorial/software/minimap2_08OCT2025_v1.sif

   executable             = ./executables/minimap2_index.sh
   arguments              = G_californianus_813.fasta

   transfer_input_files   = ./inputs/G_californianus_813.fasta

   transfer_output_files  = G_californianus_813.fasta.mmi
   transfer_output_remaps = "G_californianus_813.fasta.mmi = \
                             /staging/<netid>/genomics_tutorial/inputs/G_californianus_813.fasta.mmi"

   output                 = ./logs/$(Cluster)_$(Process)_minimap2_indexing_step1.out
   error                  = ./logs/$(Cluster)_$(Process)_minimap2_indexing_step1.err
   log                    = ./logs/$(Cluster)_minimap2_indexing_step1.log

   request_cpus           = 4
   request_disk           = 10 GB
   request_memory         = 24 GB

   queue 1
   ```

   :::{attention} The argument is the file name, not the path
   `arguments` names the FASTA file without the `inputs/` prefix. HTCondor places transferred input files in the top level of the job's scratch directory, and that is where the executable looks for them. The path belongs only in `transfer_input_files`.
   :::

   The submit file transfers the reference FASTA from your `/home` directory into the job, runs the indexing script inside the Minimap2 container, and returns the `.mmi` file. The `transfer_output_remaps` line sends the index straight to `/staging/<netid>/genomics_tutorial/inputs/` rather than to the submit directory. The index is the right kind of file for `/staging`: it is large, it is written once, and all 262 mapping jobs will read it. The `container_image` line uses an `osdf:///chtc/staging/` URL for the same reason.

## Submit and Monitor the Indexing Job

4. Submit the job:

   ```bash
   condor_submit minimap2_index.sub
   ```

5. Track its progress:

   ```bash
   condor_watch_q
   ```

   Indexing takes about ten minutes once the job starts. You can move on to [Split Your Reads](./03.5-Split-Reads.md) while you wait, because splitting does not depend on the index. Do not submit the mapping jobs until the index exists.

6. When the job has finished, confirm that the index is in your `/staging` directory:

   ```bash
   ls -lh /staging/<netid>/genomics_tutorial/inputs/
   ```

   You should see `G_californianus_813.fasta.mmi`, a file of a few gigabytes. The `.log` file in `logs/` records how much memory and disk the job actually used, which is useful when you index a different genome.

:::{warning} Do not proceed to mapping until the indexing job has completed
Every mapping job transfers `G_californianus_813.fasta.mmi` from `/staging` through OSDF. If the file is missing when the mapping jobs start, they all go on hold with a transfer error. Check with `condor_watch_q`, or look at the `.log` file in `logs/`, before submitting the mapping jobs.
:::
