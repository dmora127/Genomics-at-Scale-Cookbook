## Post-QC Steps

You should now have one FastQC report per FASTQ file in `results/`. Read them before moving on: a falling per-base quality curve toward the 3' end calls for trimming, adapter content calls for adapter removal, and overrepresented sequences that are not adapters are worth a BLAST search for contamination. The toy reads were trimmed by Data Carpentry before you downloaded them, so most checks pass; your own raw reads will be less tidy.

### Summarize All Reports with MultiQC

Six reports are easy to open one by one; six hundred are not. [MultiQC](https://multiqc.info/) collects the results of many FastQC runs into a single report. It is installed in the same container, so it runs as one more HTCondor job.

MultiQC reads the `fastqc_data.txt` inside each `_fastqc.zip` archive rather than the HTML report, so the FastQC jobs must bring the zip files back. If you have not done so, add the zip file to `many-fastqc.submit` and rerun it:

```{code} bash
:filename: many-fastqc.submit
:lineno-start: 16
transfer_output_files = $(sample).trim.sub_fastqc.html, $(sample).trim.sub_fastqc.zip
transfer_output_remaps = "$(sample).trim.sub_fastqc.html = results/$(sample).trim.sub_fastqc.html; \
                          $(sample).trim.sub_fastqc.zip = results/$(sample).trim.sub_fastqc.zip"
```

Then save the following two files in `~/tutorial-fastqc/` and submit the job with `condor_submit multiqc.sub`:

```{code} bash
:filename: multiqc.sh
:linenos:
#!/bin/bash
# Combine every FastQC result under results/ into one report
multiqc results/ --filename multiqc_report.html --no-data-dir
```

```{code} bash
:filename: multiqc.sub
:linenos:
executable             = multiqc.sh

universe               = container
container_image        = software/fastqc.sif

transfer_input_files   = results
transfer_output_files  = multiqc_report.html
transfer_output_remaps = "multiqc_report.html = results/multiqc_report.html"

log                    = logs/multiqc.log
output                 = logs/multiqc.out
error                  = logs/multiqc.err

request_cpus           = 1
request_memory         = 2GB
request_disk           = 1GB

queue 1
```

`transfer_input_files = results` transfers the whole directory, so MultiQC finds every zip archive under `results/` in the job's scratch directory. The combined report comes back to `results/multiqc_report.html`.

## Next Steps

Now that you have completed this read quality control tutorial on CHTC, you are ready to adapt the workflow to your own data and research questions. Here are some suggestions for what to do next.

### Apply the Workflow to Your Own Data

* Put your own FASTQ files in `data/` and regenerate `list_of_samples.txt`. If your files are not named `<sample>.trim.sub.fastq`, adjust the `arguments`, `transfer_input_files`, and output lines of `many-fastqc.submit` to match.
* Compressed reads (`.fastq.gz`) work with FastQC without any changes to the executable.

### Customize or Extend the Workflow

* Add read trimming as the next job per sample, with a tool such as [fastp](https://github.com/OpenGene/fastp) or [Trimmomatic](http://www.usadellab.org/cms/?page=trimmomatic), and run FastQC again on the trimmed reads.
* Continue the pipeline with the [Minimap2 read mapping](../03-Read-Mapping-with-Minimap2/03.1-Introduction.md) or the [hifiasm genome assembly](../04-Genome-Assembly-with-HiFiAsm/04.1-Introduction.md) recipe.

### Create Your Own Containers

* Extend the FastQC container with trimming tools or other dependencies, and pin the versions in the definition file.
* For help with this, see the [CHTC software guides](https://chtc.cs.wisc.edu/uw-research-computing/software-overview-htc).

### Run Larger Analyses

* Run FastQC on thousands of files with the same submit file. If the reads live in your `/staging` directory, transfer them into the jobs with `osdf:///chtc/staging/<netid>/...` URLs in `transfer_input_files` instead of `data/...` paths.
* Chain quality control, trimming, and mapping into one workflow with [DAGMan](https://chtc.cs.wisc.edu/uw-research-computing/dagman-workflows).

### Get Help or Collaborate

* Reach out to [chtc@cs.wisc.edu](mailto:chtc@cs.wisc.edu) for one-on-one help with scaling your research.
* Attend office hours or training sessions. See the [CHTC Get Help page](https://chtc.cs.wisc.edu/uw-research-computing/get-help.html) for details.

## Software

In this tutorial you used an Apptainer container with FastQC and MultiQC. The container recipe can serve as a jumping-off point if you need to install additional software for your workflows.

Our recommendation for most users is to use Apptainer containers for deploying their software. For instructions on how to build an Apptainer container, see the guide [Using Apptainer/Singularity Containers](https://chtc.cs.wisc.edu/uw-research-computing/apptainer-htc). If you are familiar with Docker, or want to learn how to use Docker, see the guide [Using Docker Containers](https://chtc.cs.wisc.edu/uw-research-computing/docker-jobs).

This information can also be found in the guide [Using Software on CHTC](https://chtc.cs.wisc.edu/uw-research-computing/software-overview-htc).
