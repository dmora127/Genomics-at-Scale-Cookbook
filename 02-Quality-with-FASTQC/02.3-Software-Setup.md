(fastqc-software-setup)=
FastQC runs inside an Apptainer container in this tutorial. HTCondor starts the container on the execute point for every job, so you never install FastQC on the Access Point or on the execute point yourself. The container recipe ships with the repository, and building it takes a few minutes in an interactive build job.

:::{note} About `download_software.sh`
The repository also ships a `download_software.sh` script that fetches a prebuilt `fastqc.sif` from a CHTC web proxy at `proxy.chtc.wisc.edu`. That hostname no longer resolves (checked from a CHTC execute point in October 2026), so the script fails. Build the image as described below instead; the result is the same container.
:::

If you are not already logged into a CHTC Access Point (AP), do so now via SSH:

```bash
ssh <netid>@ap2001.chtc.wisc.edu
cd ~/tutorial-fastqc/
```

:::{seealso} Never Built an Apptainer Container Before?
If you have never built an Apptainer container before, refer to the [Apptainer Container Building Guide](https://chtc.cs.wisc.edu/uw-research-computing/apptainer-htc) for more information on building Apptainer containers on CHTC.
:::

## Review the FastQC Definition File

1. The repository ships the container recipe as `software/fastqc.def`. It starts from a Miniconda base image, installs FastQC from the bioconda channel, and installs MultiQC with pip:

   ```{code} bash
   :filename: software/fastqc.def
   :linenos:
   :emphasize-lines: 9
   Bootstrap: docker
   From: continuumio/miniconda3:24.3.0-0

   # Created by Patricia Tran
   # https://orcid.org/0000-0003-3948-3938
   # https://github.com/UW-Madison-Bacteriology-Bioinformatics/chtc-containers

   %post
       conda install -y bioconda::fastqc
       pip install multiqc
   ```

   :::{attention} Add `-y` to the `conda install` line
   The cloned `fastqc.def` runs `conda install bioconda::fastqc` without `-y`. A container build is not interactive, so conda has nobody to answer its confirmation prompt and the build can stall. Add `-y` before you build, as shown on line 9. When you adapt the recipe for your own work, also pin the versions, for example `bioconda::fastqc=0.13.0` and `multiqc==1.35`, so that rebuilding the container later gives you the same software.
   :::

## Build Your FastQC Apptainer Container Interactively

### Write Your `build.sub` Submit File

2. Create a submit file for an interactive build job. Open a text editor, such as `vim` or `nano`, and save the following as `software/build.sub`:

   ```{code} bash
   :filename: software/build.sub
   :linenos:
   :emphasize-lines: 3
   log = build.log

   transfer_input_files = software/fastqc.def

   +IsBuildJob = True

   request_cpus = 4
   request_memory = 8GB
   request_disk = 10GB

   queue
   ```

   The `+IsBuildJob = True` attribute sends the job to a dedicated container-building execute point. Submit it from the top of the repository so that the `transfer_input_files` path resolves.

   :::{caution} Never build containers on the Access Point or in a standard job
   Building a container needs permissions and resources that only the dedicated build nodes provide. Do not run `apptainer build` on the Access Point, which is a shared machine, and do not submit the build as an ordinary job.
   :::

### Build Your FastQC Apptainer Container

3. Submit the build job as an interactive job:

   ```bash
   condor_submit -i software/build.sub
   ```

   HTCondor waits for a build node, then drops you into a shell on it. Your prompt changes from `ap2001` to a `build` hostname, and `fastqc.def` is waiting in the job's scratch directory.

4. Build the image. Include the software name, build date, and a version number in the file name, because you will want to tell images apart later:

   ```bash
   apptainer build fastqc_15OCT2026_v1.sif fastqc.def
   ```

   The build downloads the base image and the conda packages and takes a few minutes.

5. Exit the interactive job:

   ```bash
   exit
   ```

   When you exit, HTCondor transfers the new `.sif` file back to the directory you submitted from.

## Place the Image in `software/`

6. Move the image into `software/` and point the submit files at it. Either rename it to `software/fastqc.sif`, which is the name both submit files expect, or keep the dated name and update the `container_image` line in `fastqc.submit` and `many-fastqc.submit`:

   ```bash
   mv fastqc_15OCT2026_v1.sif software/fastqc.sif
   ```

7. Confirm that the image is in place:

   ```
   [<netid>@ap2001 tutorial-fastqc]$ ls software/
   build.sub  fastqc.def  fastqc.sif
   ```

:::{tip} Where should a container image live?
The FastQC image is around a gigabyte, and HTCondor copies it from `/home` to the execute point for every job. That is acceptable for a handful of jobs. For hundreds of jobs, or for larger images, put the image in your `/staging` directory and reference it with an `osdf:///chtc/staging/<netid>/...` URL in `container_image`, as the [Dorado](../01-Basecalling-GPUs/01.5-Basecall-Reads.md) and [Minimap2](../03-Read-Mapping-with-Minimap2/03.6-Map-Reads.md) recipes do. See the CHTC guide on [using Apptainer containers](https://chtc.cs.wisc.edu/uw-research-computing/apptainer-htc) for details.
:::
