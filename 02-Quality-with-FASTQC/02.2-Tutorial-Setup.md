## Before You Begin

You will need the following before moving forward with the tutorial:

1. A CHTC HTC account. If you do not have one, request access at the [CHTC Account Request Page](https://chtc.cs.wisc.edu/uw-research-computing/form.html).
2. Basic familiarity with HTCondor job submission. If you are new to HTCondor, complete the CHTC [Roadmap to getting started](https://chtc.cs.wisc.edu/uw-research-computing/htc-roadmap) and read [Practice: Submit HTC Jobs using HTCondor](https://chtc.cs.wisc.edu/uw-research-computing/htcondor-job-submission).
3. Basic familiarity with the Linux command line. If you are new to the command line, consider working through the [Unix Shell](https://swcarpentry.github.io/shell-novice/) lesson from Software Carpentry.
4. About 2 GB of free space in your `/home` directory for the container image and the reads. Check with `quota -vs`; see the CHTC guide on [checking disk quota and usage](https://chtc.cs.wisc.edu/uw-research-computing/check-quota).

You do **not** need a `/staging` directory for this recipe. The reads and the container are small enough to live in `/home` and to be transferred by HTCondor directly.

:::{hint} No need to be a genomics expert!
You do not need to be a genomics expert to follow this tutorial. The commands and scripts are beginner-friendly and self-contained while reflecting real-world research workflows.
:::

:::{note} Versions used in this tutorial
| Component | Value |
|-----------|-------|
| FastQC | 0.13.0 (bioconda release current in October 2026; the recipe does not pin it) |
| MultiQC | 1.35 (PyPI release current in October 2026; the recipe does not pin it) |
| Container base image | `continuumio/miniconda3:24.3.0-0` |
| Container image | `software/fastqc.sif`, built from `software/fastqc.def` in [Set Up Your Software Environment](#fastqc-software-setup) |
| Toy dataset | Data Carpentry *Wrangling Genomics* subsampled reads (`sub.tar.gz`, figshare file 14418248) |

The container recipe `software/fastqc.def` does not pin the FastQC or MultiQC versions, so a container you build yourself will pick up whatever bioconda and PyPI serve that day. Pin the versions in the recipe when you adapt it for your own work.
:::

## Materials

Log into a CHTC Access Point (AP):

```bash
ssh <netid>@ap2001.chtc.wisc.edu
```

Clone the companion tutorial repository, which contains the executable, submit files, download scripts, and container definition used in this tutorial:

```bash
git clone https://github.com/CHTC/tutorial-fastqc.git
cd tutorial-fastqc/
```

## About the Toy Dataset

The toy dataset is the subsampled, trimmed set of reads that [Data Carpentry](https://datacarpentry.org/) uses in its [Wrangling Genomics](https://datacarpentry.github.io/wrangling-genomics/) lesson. The reads are paired-end Illumina whole-genome sequencing reads from the *Escherichia coli* Ara-3 population of Richard Lenski's long-term evolution experiment, in which *E. coli* evolved the ability to use citrate ([Blount et al. 2008, PNAS](https://www.pnas.org/doi/10.1073/pnas.0803151105)). Three samples were sequenced, taken at 5,000, 15,000, and 50,000 generations, and each sample has a forward (`_1`) and a reverse (`_2`) read file. Data Carpentry trimmed and subsampled the reads so that the files are small enough for a workshop; see the lesson for how the data were prepared.

The repository ships a script that downloads the archive from figshare and unpacks it into `data/`:

```bash
./download_data.sh
```

List the directory to confirm that you have six FASTQ files:

```
[<netid>@ap2001 tutorial-fastqc]$ ls data/
SRR2584863_1.trim.sub.fastq  SRR2584866_1.trim.sub.fastq  SRR2589044_1.trim.sub.fastq
SRR2584863_2.trim.sub.fastq  SRR2584866_2.trim.sub.fastq  SRR2589044_2.trim.sub.fastq
```

## Time Estimation

Plan about 30-45 minutes for the tutorial walkthrough. Each FastQC job runs in well under a minute; most of the elapsed time is the wait for jobs to be matched to an execute point, which is typically a few minutes.

## Recommended Directory Structure

The cloned repository has the layout below. The `data/`, `results/`, and `software/` directories start empty and fill up as you work through the tutorial:

```bash
./tutorial-fastqc/
├── data/                      # FASTQ files, filled by download_data.sh
├── download_data.sh           # fetches the toy dataset into data/
├── download_software.sh       # fetches the prebuilt FastQC container into software/
├── fastqc.sh                  # executable run by each job
├── fastqc.submit              # submit file for a single job
├── many-fastqc.submit         # submit file for one job per sample
├── list_of_samples.txt        # one sample name per line (created in Scale Out)
├── logs/                      # HTCondor .log, .out, and .err files
├── results/                   # FastQC reports returned by the jobs
├── software/
│   ├── fastqc.def             # container recipe
│   └── fastqc.sif             # container image (downloaded or built in Software Setup)
├── FastQC_Tutorial.md         # the tutorial, as a GitHub README
├── FastQC_Tutorial.ipynb      # notebook version of the same tutorial
└── README.md
```
