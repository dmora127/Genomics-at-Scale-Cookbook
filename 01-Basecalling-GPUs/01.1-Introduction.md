This tutorial guides you through the first step of a long-read sequencing analysis workflow, basecalling, using Oxford Nanopore data on the CHTC high-throughput computing (HTC) system. You will learn how to:

* Basecall raw Nanopore reads with the Dorado basecaller
* Use CHTC's GPU capacity to accelerate basecalling with Dorado
* Break a large basecalling workload into many small, independent jobs
* Submit hundreds to thousands of jobs with a few commands
* Move containers and basecalling models into jobs with the Open Science Data Federation (OSDF)

The steps of this tutorial run across hundreds (or thousands) of jobs using the HTCondor workload manager and Apptainer containers to execute your software reliably and reproducibly at scale. The tutorial uses a real, publicly available Nanopore dataset and emphasizes performance, reproducibility, and portability.

## Understanding Basecalling in Oxford Nanopore Sequencing

In Oxford Nanopore Technologies (ONT) sequencing, the instrument does not directly read DNA or RNA bases. Instead, it measures subtle changes in ionic current as a single-stranded molecule passes through a nanopore embedded in a membrane. These electrical current traces, often called raw signals or squiggles, reflect the sequence of the nucleotides inside the pore.

### From Signal to Sequence: The Role of Basecalling

Basecalling converts continuous electrical signals into nucleotide sequences (A, C, G, T, or U). Basecalling algorithms interpret the temporal and amplitude patterns in the current signal to infer the most probable sequence of bases. This step is one of the most computationally demanding parts of the ONT analysis pipeline.

Dorado uses deep neural network models trained to map signal patterns to their corresponding base sequences. These models rely on GPU acceleration to perform millions of operations per second. GPUs dramatically shorten inference time by parallelizing the math behind neural network prediction, enabling accurate and high-throughput decoding of long-read data.

Because each read, and therefore each POD5 file, can be basecalled independently, Dorado workflows scale well on CHTC, where many GPU jobs can run at the same time. CHTC provides the GPU capacity, the `/staging` file system, and OSDF-based transfers needed to handle large sequencing runs reproducibly and efficiently. You can turn hours of basecalling on a single workstation into minutes of parallel basecalling across the pool.

## Basecalling by Sequencing Channel

Each Oxford Nanopore flow cell contains hundreds to thousands of channels that generate independent signal traces, so the data in a single POD5 file can be subdivided into smaller, channel-specific subsets. By splitting the data so that each channel's reads are in their own POD5 file, you enable true parallel basecalling: each channel file becomes an independent job that can run simultaneously across hundreds of CHTC GPU execute points. This design follows the central principle of HTC: many small, independent jobs working together to finish a large workload quickly. Splitting by channel also keeps duplex read pairs together, because the template and complement strands of a duplex read pass through the same pore one after the other.

To split reads by channel, use the `pod5` package installed in your Dorado container to generate per-channel subsets in a `split_pod5_subsets/` directory. Once subdivided, each new POD5 file can be basecalled individually, dramatically reducing time-to-results while maintaining reproducibility and scalability.
