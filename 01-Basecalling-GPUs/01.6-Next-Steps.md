## Post-Basecalling Steps

You should now have a directory of basecalled FASTQ and BAM files in your `outputs/` folder. You will likely want to perform additional steps after basecalling, such as checking read quality, mapping to a reference genome, or calling variants. We recommend merging your basecalled FASTQ files into a single file for downstream analysis. You can do this using the `cat` command:

```bash
for f in outputs/basecalledFASTQs/*.fastq; do
    cat "$f" >> outputs/merged_basecalled_reads.fastq
done
```

Use this merged FASTQ file for quality control, mapping, or variant calling. The recommended next step is to run FastQC to assess the quality of your basecalled reads; CHTC maintains a [FastQC tutorial repository](https://github.com/CHTC/tutorial-fastqc) you can adapt.

## Next Steps

Now that you have completed this long-read basecalling tutorial on CHTC, you are ready to adapt the workflow to your own data and research questions. Here are some suggestions for what to do next.

### Apply the Workflow to Your Own Data

* Replace the tutorial dataset with your own POD5 files.
* Modify the basecalling submit file to fit your data size, read type (e.g. simplex vs. duplex), and resource needs.

### Customize or Extend the Workflow

* Incorporate quality control steps (e.g. filtering or read statistics) using FastQC.
* Add downstream tools for mapping, annotation, comparison, or visualization (e.g. minimap2, IGV, bedtools, SURVIVOR).

### Create Your Own Containers

* Extend the Apptainer container used here with additional tools, reference data, or dependencies.
* For help with this, see the [CHTC software guides](https://chtc.cs.wisc.edu/uw-research-computing/software-overview-htc).

### Run Larger Analyses

* Submit thousands of basecalling jobs across CHTC.
* Explore data staging best practices for large-scale genomics workflows, including OSDF.
* Consider using workflow managers (e.g. [DAGMan](https://chtc.cs.wisc.edu/uw-research-computing/dagman-workflows)) with HTCondor.

### Get Help or Collaborate

* Reach out to [chtc@cs.wisc.edu](mailto:chtc@cs.wisc.edu) for one-on-one help with scaling your research.
* Attend office hours or training sessions. See the [CHTC Get Help page](https://chtc.cs.wisc.edu/uw-research-computing/get-help.html) for details.

## Software

In this tutorial you built a *starter* Apptainer container with Dorado, `pod5`, and `bedtools`. This container can serve as a jumping-off point if you need to install additional software for your workflows.

Our recommendation for most users is to use Apptainer containers for deploying their software. For instructions on how to build an Apptainer container, see the guide [Using Apptainer/Singularity Containers](https://chtc.cs.wisc.edu/uw-research-computing/apptainer-htc). If you are familiar with Docker, or want to learn how to use Docker, see the guide [Using Docker Containers](https://chtc.cs.wisc.edu/uw-research-computing/docker-jobs).

This information can also be found in the guide [Using Software on CHTC](https://chtc.cs.wisc.edu/uw-research-computing/software-overview-htc).

## Data

The ecosystem for moving data to, from, and within the HTC system can be complex, especially when working with large data (many gigabytes). For guides on how data movement works on the HTC system, see the [Data Staging and Transfer to Jobs](https://chtc.cs.wisc.edu/uw-research-computing/htc-job-file-transfer) guides.
