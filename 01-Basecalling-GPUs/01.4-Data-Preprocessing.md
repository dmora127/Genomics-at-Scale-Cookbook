This section covers a key preparatory step before submitting your basecalling jobs to CHTC: splitting your POD5 files by sequencing channel.

## Split Your Reads for Basecalling

When basecalling sequencing data with Dorado, you can subdivide your POD5 files into smaller, independent subsets. This subdivision lets you take advantage of high-throughput computing (HTC) principles and significantly decreases the time-to-results for your basecalling. You will use the `pod5` package installed in your Dorado container. If you have not built the `dorado_build1.2.0_27OCT2025_v1.sif` Apptainer image yet, refer to [Set Up Your Software Environment](#dorado-software-setup).

:::{tip} One-step alternative
The tutorial repository includes `executables/preprocessing_pod5s.sh`, which runs steps 3, 4, and 6 below in one go. Run it from inside the Apptainer shell as `bash executables/preprocessing_pod5s.sh inputs/`. The individual steps are shown here so you understand what the script does.
:::

1. Move to your `inputs/` directory, where your POD5 files are located:

   ```bash
   cd ~/tutorial-ONT-Basecalling/inputs/
   ```

2. Launch an interactive Apptainer shell session on the Access Point (AP) using your `dorado_build1.2.0_27OCT2025_v1.sif` container:

   ```bash
   apptainer shell --bind "$PWD" /staging/<netid>/tutorial-ONT-Basecalling/software/dorado_build1.2.0_27OCT2025_v1.sif
   ```

3. Create a table mapping each read ID to its channel:

   ```bash
   pod5 view <pod5_dir> --include "read_id, channel" --output summary.tsv
   ```

   _This generates a TSV table mapping each read_id to its channel. Replace `<pod5_dir>` with `./` if you are in the directory that contains your POD5 files._

4. Subset your POD5 reads by channel using the `summary.tsv` table created in the previous step. Output the POD5 subsets to `split_pod5_subsets/`:

   ```bash
   pod5 subset <pod5_dir> --summary summary.tsv --columns channel --output split_pod5_subsets
   ```

   Your `--output` path `split_pod5_subsets/` should point to a path in your `/home` directory on the AP, **not** your `/staging` directory. After this command completes, the `split_pod5_subsets/` directory contains one subsetted POD5 file per sequencing channel on the flow cell.

   :::{warning} This step **will** take a while. Only write the output to your `/home` directory!
   **This step will take a while, depending on the size of your POD5 files and the number of channels present in your data.** It generates one POD5 file per channel in the `split_pod5_subsets/` output directory. A MinION flow cell has 512 channels, so expect roughly 512 POD5 files in your output directory (PromethION flow cells have more).

   **Never write your subsetted POD5 files to `/staging`.** `/staging` is designed for large files, and writing hundreds of small files to it strains the shared storage system for everyone and violates the CHTC `/staging` usage policy. Only write your subsetted POD5 files to your `/home` directory on the AP.
   :::

5. Exit the Apptainer shell:

   ```bash
   exit
   ```

   _You may have to run `exit` more than once to leave the Apptainer shell and return to your normal bash shell._

6. Create a list of POD5 files to iterate through during job submission:

   ```bash
   ls split_pod5_subsets > ~/tutorial-ONT-Basecalling/list_of_pod5_files.txt
   ```

   If you `head` this new file you should see output similar to this:

   ```
   [<netid>@ap2001 inputs]$ head ~/tutorial-ONT-Basecalling/list_of_pod5_files.txt
   channel-100.pod5
   channel-101.pod5
   channel-102.pod5
   channel-103.pod5
   channel-104.pod5
   channel-105.pod5
   channel-106.pod5
   channel-107.pod5
   channel-108.pod5
   channel-109.pod5
   [<netid>@ap2001 inputs]$
   ```
