## Before You Begin

You will need the following before moving forward with the tutorial:

1. A CHTC HTC account. If you do not have one, request access at the [CHTC Account Request Page](https://chtc.cs.wisc.edu/uw-research-computing/form.html).
2. A CHTC `/staging` directory for large files. If you do not have one, request it through the [CHTC large data guide](https://chtc.cs.wisc.edu/uw-research-computing/file-avail-largedata).
3. Basic familiarity with HTCondor job submission. If you are new to HTCondor, complete the CHTC [Roadmap to getting started](https://chtc.cs.wisc.edu/uw-research-computing/htc-roadmap) and read [Practice: Submit HTC Jobs using HTCondor](https://chtc.cs.wisc.edu/uw-research-computing/htcondor-job-submission).
4. Basic familiarity with the Linux command line. If you are new to the command line, consider working through the [Unix Shell](https://swcarpentry.github.io/shell-novice/) lesson from Software Carpentry.
5. A general understanding of the long-read sequencing analysis workflow. If you are new to long-read sequencing, review introductory materials such as the [Oxford Nanopore Technologies website](https://nanoporetech.com/) or relevant literature.
6. Sufficient disk quota and file permissions in your `/home` and `/staging` directories (the toy dataset alone is about 15 GB).

:::{hint} No need to be a genomics expert!
You do not need to be a genomics expert to follow this tutorial. The commands and scripts are beginner-friendly and self-contained while reflecting real-world research workflows.
:::

:::{note} Versions used in this tutorial
| Component | Value |
|-----------|-------|
| Dorado | 1.2.0 |
| Basecalling model | `dna_r10.4.1_e8.2_400bps_hac@v5.2.0` |
| Container base image | `nvidia/cuda:13.0.1-cudnn-runtime-ubuntu22.04` |
| Container image built in this tutorial | `dorado_build1.2.0_27OCT2025_v1.sif` (27 October 2025) |

Newer Dorado releases follow the same workflow. When you adapt the tutorial, update the version numbers in the definition file, the container image name, and the model name together.
:::

## Materials

Log into a CHTC Access Point (AP):

```bash
ssh <netid>@ap2001.chtc.wisc.edu
```

Clone the companion tutorial repository, which contains the executables, submit files, and container definition used in this tutorial:

```bash
git clone https://github.com/dmora127/tutorial-ONT-Basecalling.git
cd tutorial-ONT-Basecalling/
```

Then create the companion `/staging` directories that will hold your container image and basecalling models:

```bash
mkdir -p /staging/<netid>/tutorial-ONT-Basecalling/software /staging/<netid>/tutorial-ONT-Basecalling/data
```

:::{note} About `tutorial-setup.sh`
The repository ships a `tutorial-setup.sh` helper that creates the same directory layout on the OSPool (under `/ospool/ap40/data/`). On CHTC, use the `mkdir` command above instead.
:::

## About the Toy Dataset

The toy dataset is a subset of a publicly available Oxford Nanopore release of _Drosophila melanogaster_ (Berkeley Drosophila Genome Project iso-1 strain), sequenced for DNA on R10.4.1 flow cells with Kit 14 chemistry; see the [ONT Open Data registry](https://registry.opendata.aws/ont-open-data/). The POD5 files were generated from the deposited FAST5 files with the `pod5` tool from Oxford Nanopore Technologies:

```bash
pod5 convert fast5 </path/to/input_FAST5s> --output </path/to/output_pod5s> --one-to-one
```

The POD5 files are too large for the git repository, so CHTC hosts them in a shared `/staging` directory. Extract them into your `inputs/` directory:

```bash
tar -xzf /staging/groups/chtc_staff/tutorial-ont-basecalling/inputs/dmel_pod5s.tar.gz --strip-components=2 -C ~/tutorial-ONT-Basecalling/inputs/
```

:::{warning} Check your `/home` quota first
The archive expands to roughly 15 GB of POD5 files, and the split-by-channel step later writes a similar amount again. Check your `/home` quota and usage with `quota -vs` before extracting; see the CHTC guide on [checking disk quota and usage](https://chtc.cs.wisc.edu/uw-research-computing/check-quota). If you need more space, request a quota increase through the [CHTC large data guide](https://chtc.cs.wisc.edu/uw-research-computing/file-avail-largedata).
:::

You can use these files to practice basecalling with Dorado on CHTC. The dataset is small enough to complete the tutorial in a reasonable amount of time, while still being representative of real-world data.

## Time Estimation

Plan about 1-2 hours for the tutorial walkthrough. Each basecalling job typically takes 30 minutes or more depending on dataset size and cluster load. Small test runs often complete in 10-30 minutes.

## Recommended Directory Structure

The cloned repository has the layout below. The `inputs/`, `logs/`, and `outputs/` directories start empty and fill up as you work through the tutorial:

```bash
./tutorial-ONT-Basecalling/
├── executables/                       # scripts for preprocessing POD5 files and running Dorado
│   ├── preprocessing_pod5s.sh         # optional one-step split-by-channel helper
│   └── run_dorado.sh                  # executable run by each basecalling job
├── inputs/                            # raw POD5 files; split_pod5_subsets/ is created here
├── list_of_pod5_files.txt             # one POD5 subset file name per line (created in Data Preprocessing)
├── logs/                              # HTCondor .log files
│   ├── err/                           # job stderr
│   └── out/                           # job stdout
├── outputs/                           # basecalled outputs (BAM/FASTQ)
├── README.md                          # the tutorial, as a GitHub README
├── run_dorado_at_CHTC.sub             # HTCondor submit file used in this tutorial (CHTC)
├── run_dorado.sub                     # HTCondor submit file for the OSPool (not used here)
├── software/                          # container recipes
│   └── dorado.def
└── tutorial-setup.sh                  # helper for the OSPool directory layout (not used here)
```

You also have a companion **`/staging`** directory for storing large files, such as the container image and the Dorado model, which you will populate in [Set Up Your Software Environment](./01.3-Software-Setup.md):

```bash
/staging/<netid>/tutorial-ONT-Basecalling/
├── data/
│   └── dna_r10.4.1_e8.2_400bps_hac@v5.2.0.tar.gz
└── software/
    └── dorado_build1.2.0_27OCT2025_v1.sif
```
