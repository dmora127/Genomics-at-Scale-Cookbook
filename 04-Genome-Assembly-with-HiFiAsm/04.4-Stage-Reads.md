The assembly job reads the Nanopore reads directly from your `/staging` directory, so the reads have to be there before you submit. This page downloads them from OSDF with Pelican, explains why the job reads them in place rather than transferring them, and shows how to make a small subset for a test run.

## Download the Reads with Pelican

1. Change to your `tutorial-CHTC-Genome-Assembly/` directory:

   ```bash
   cd ~/tutorial-CHTC-Genome-Assembly/
   ```

2. Download the reads into your `/staging` tutorial directory. The `pelican` client is installed on the Access Point:

   ```bash
   pelican object get osdf:///osg-public/data/tutorial-CHTC-Genome-Assembly/SRR22085263.fastq \
       /staging/<netid>/tutorial-CHTC-Genome-Assembly/SRR22085263.fastq
   ```

   :::{note} What to expect from the download
   The file is 318 GB and the download takes about an hour. Run it inside a `screen` or `tmux` session so that it survives a dropped SSH connection. If Pelican asks you to create a Pelican password or to sign in through a URL, create a short passphrase you will remember, open the URL in your browser, sign in with your UW-Madison NetID, and approve the request.
   :::

   :::{seealso} Pelican and OSDF
   Pelican is the client for the Open Science Data Federation, the same system that delivers `osdf:///` URLs in submit files. See the CHTC guide on [transferring data with Pelican](https://chtc.cs.wisc.edu/uw-research-computing/pelican) for other ways to move large data in and out of `/staging`.
   :::

3. When the download finishes, confirm the file is complete. `ls -lh` reports the size in binary units, so 318 GB shows as `296G`:

   ```
   [<netid>@ap2001 tutorial-CHTC-Genome-Assembly]$ ls -lh /staging/<netid>/tutorial-CHTC-Genome-Assembly/
   total 296G
   drwxr-xr-x 2 <netid> <netid>    0 Oct 15 14:02 Assembly_Output
   -rw-r--r-- 1 <netid> <netid> 296G Oct 15 15:10 SRR22085263.fastq
   ```

## Read in Place Instead of Transferring

The other recipes in this cookbook put input files in `transfer_input_files` and let HTCondor copy them into the job. This recipe does not, for two reasons:

* **Size.** Copying 318 GB into the job's scratch directory would need 318 GB of extra `request_disk` and would add the transfer time to every attempt.
* **No reuse.** OSDF caches files so that many jobs can fetch the same file quickly. One job reading one file gains nothing from the cache.

Instead, the submit file keeps the job on a CHTC execute point that mounts `/staging` with `requirements = (Target.HasCHTCStaging == true)`, and the executable opens `/staging/<netid>/tutorial-CHTC-Genome-Assembly/SRR22085263.fastq` directly. This is the recommended pattern on CHTC for a single job that reads a very large file; see the CHTC guide on [using /staging for large data](https://chtc.cs.wisc.edu/uw-research-computing/file-avail-largedata).

Switch back to `transfer_input_files` with an `osdf:///chtc/staging/<netid>/...` URL when the job must run outside CHTC, for example on the OSPool, where `/staging` is not mounted, or when many jobs read the same file.

## Prepare Your Own Reads

When you adapt this recipe to your own data:

* **Keep the reads compressed.** hifiasm reads `.fastq.gz` directly, and gzip shrinks Nanopore FASTQ by roughly four to five times, which cuts both storage and transfer time. Compress large files in a job, not on the Access Point.
* **Concatenate multiple runs** before staging them. Concatenated gzip files are still valid gzip:

  ```bash
  cat run1.fastq.gz run2.fastq.gz run3.fastq.gz > all_reads.fastq.gz
  ```

* **Basecall first.** If you have raw POD5 files rather than FASTQ, the [Dorado recipe](../01-Basecalling-GPUs/01.1-Introduction.md) produces the reads this recipe consumes.

:::{tip} Test with a subset first
Before committing to a 4-12 hour job, run the whole pipeline on the first 100,000 reads (400,000 FASTQ lines). The resulting assembly is meaningless at that coverage, but it proves that the container, the script, the paths, and the output transfer all work:

```bash
head -n 400000 /staging/<netid>/tutorial-CHTC-Genome-Assembly/SRR22085263.fastq \
    > /staging/<netid>/tutorial-CHTC-Genome-Assembly/SRR22085263_subset.fastq
```

Then, in the next page, submit `assembly.sub` with the subset path in `arguments`, `request_cpus = 8`, `request_memory = 16GB`, and `request_disk = 100GB`. The test job finishes in minutes.
:::
