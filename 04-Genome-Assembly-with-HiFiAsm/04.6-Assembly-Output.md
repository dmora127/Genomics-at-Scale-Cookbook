Once the assembly job completes, the packaged results are in your `/staging` directory. This page unpacks them, explains what each file is, and shows a few quick checks.

## Extract the Output

1. Change to the output directory in `/staging` and extract the tarball there. The archive holds a handful of large files, which is what `/staging` is for:

   ```bash
   cd /staging/<netid>/tutorial-CHTC-Genome-Assembly/Assembly_Output/
   tar xzf assembly_output.tar.gz
   ls -lh
   ```

2. hifiasm produces several output files, all prefixed with the `Omalun-Tater` name passed in `arguments`:

   | File                                 | Description                                              |
   |--------------------------------------|----------------------------------------------------------|
   | `Omalun-Tater.asm.bp.hap1.p_ctg.gfa` | Haplotype 1 primary contigs (assembly graph)             |
   | `Omalun-Tater.asm.bp.hap2.p_ctg.gfa` | Haplotype 2 primary contigs (assembly graph)             |
   | `Omalun-Tater.asm.bp.p_ctg.gfa`      | Combined primary contigs (assembly graph)                |
   | `Omalun-Tater.asm.bp.hap1.p_ctg.fa`  | Haplotype 1 primary contigs (FASTA, converted by the script) |
   | `Omalun-Tater.asm.bp.hap2.p_ctg.fa`  | Haplotype 2 primary contigs (FASTA, converted by the script) |
   | `Omalun-Tater.asm.bp.p_ctg.fa`       | Combined primary contigs (FASTA, converted by the script) |
   | `Omalun-Tater.asm.ec.bin`            | Error-corrected reads (binary)                           |
   | `Omalun-Tater.asm.ovlp.*.bin`        | Overlap information (binary)                             |

   The **GFA** (Graphical Fragment Assembly) files contain the assembly graph, which captures the full structure of the assembly including alternative paths. The **FASTA** files are derived from the GFA files by extracting the contig sequences, which `assembly.sh` did at the end of the job. The `.bin` files let hifiasm rerun with different parameters without recomputing the overlaps, as long as you use the same hifiasm version.

## Haplotype-Resolved Assembly

hifiasm produces **haplotype-resolved** assemblies, meaning it separates the two parental copies of the genome into distinct outputs (`hap1` and `hap2`). This is particularly valuable for:

* Studying structural variation between haplotypes
* Phasing heterozygous variants
* Generating more complete genome representations

The combined primary contigs (`Omalun-Tater.asm.bp.p_ctg.fa`) represent a merged view and are suitable for most downstream applications.

## Quick Assembly Statistics

3. Count the contigs and add up their length. These one-liners run quickly even on a 2.4 Gb assembly:

   ```bash
   # Number of contigs
   grep -c "^>" Omalun-Tater.asm.bp.p_ctg.fa

   # Number of contigs and total assembled length in bp
   awk '/^>/{n++; next}{len+=length($0)} END{print n " contigs, " len " bp"}' Omalun-Tater.asm.bp.p_ctg.fa

   # The first few contig headers
   head -n 20 Omalun-Tater.asm.bp.p_ctg.fa | grep "^>"
   ```

   A total length near 2.4 Gb in a few hundred contigs or fewer is what to expect from a good Nanopore assembly of this genome. For the standard contiguity and completeness metrics (N50, L50, BUSCO scores), run an assessment tool such as QUAST or BUSCO as a follow-up job; see [Next Steps](./04.7-Next-Steps.md).

## Visualize the Assembly Graph

4. [Bandage](https://rrwick.github.io/Bandage/) draws GFA assembly graphs interactively. Copy a GFA file to your own computer and open it in Bandage. Run this on your laptop, not on the Access Point, and expect the file to be several gigabytes:

   ```bash
   scp <netid>@ap2001.chtc.wisc.edu:/staging/<netid>/tutorial-CHTC-Genome-Assembly/Assembly_Output/Omalun-Tater.asm.bp.p_ctg.gfa .
   ```
