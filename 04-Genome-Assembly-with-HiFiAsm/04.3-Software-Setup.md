(hifiasm-software-setup)=
hifiasm runs inside an Apptainer container in this tutorial, and CHTC has already built and published the image. The submit file points HTCondor at it with an OSDF URL:

```
container_image = osdf:///osg-public/containers/hifiasm_08APR2026_v1.sif
```

HTCondor fetches the 370 MB image through OSDF and starts the job inside it. There is nothing to download, build, or copy, so you can continue to [Stage Your Nanopore Reads](./04.4-Stage-Reads.md). Build your own image only if you need a different hifiasm version or extra tools in the same container.

::::{dropdown} Build your own hifiasm container (optional)

:::{seealso} Never Built an Apptainer Container Before?
If you have never built an Apptainer container before, refer to the [Apptainer Container Building Guide](https://chtc.cs.wisc.edu/uw-research-computing/apptainer-htc) for more information on building Apptainer containers on CHTC.
:::

1. Review the container recipe `software/hifiasm.def`. It starts from a Miniforge base image and installs hifiasm from bioconda with mamba:

   ```{code} bash
   :filename: software/hifiasm.def
   :linenos:
   Bootstrap: docker
   From: condaforge/miniforge3:latest

   %post
       mamba install -c conda-forge -c bioconda hifiasm
   ```

   Pin the version when you adapt this recipe, for example `mamba install -y -c conda-forge -c bioconda hifiasm=0.25.0`, so that rebuilding later gives you the same assembler.

2. Review the interactive build submit file `software/build.sub`:

   ```{code} bash
   :filename: software/build.sub
   :linenos:
   # apptainer.sub

   # Include other files that need to be transferred here.
   transfer_input_files = hifiasm.def

   +IsBuildJob = True

   # Make sure you request enough disk for the container image to build
   request_cpus = 8
   request_memory = 16GB
   request_disk = 30GB

   queue
   ```

   The `transfer_input_files` path is relative to the directory you submit from, so submit this file from inside `software/`.

3. Submit the build job as an interactive job:

   ```bash
   cd ~/tutorial-CHTC-Genome-Assembly/software/
   condor_submit -i build.sub
   ```

   HTCondor waits for a build node, then drops you into a shell on it with `hifiasm.def` in the job's scratch directory.

   :::{caution} Never build containers on the Access Point or in a standard job
   Building a container needs permissions and resources that only the dedicated build nodes provide, which is what `+IsBuildJob = True` requests. A standard job will fail, and building on the Access Point slows the machine down for every other user and violates CHTC's usage policies.
   :::

4. Build the image, with the software name, build date, and a version number in the file name:

   ```bash
   apptainer build hifiasm_15OCT2026_v1.sif hifiasm.def
   ```

5. Move the image to a `software/` directory in your `/staging` tutorial directory:

   ```bash
   mkdir -p /staging/<netid>/tutorial-CHTC-Genome-Assembly/software/
   mv hifiasm_15OCT2026_v1.sif /staging/<netid>/tutorial-CHTC-Genome-Assembly/software/
   ```

6. Exit the interactive build job to return to the Access Point:

   ```bash
   exit
   ```

7. Point the submit file at your image by replacing the `container_image` line in `assembly.sub`:

   ```
   container_image = osdf:///chtc/staging/<netid>/tutorial-CHTC-Genome-Assembly/software/hifiasm_15OCT2026_v1.sif
   ```

   OSDF caches files by name, so give every rebuilt image a new date or version number.
